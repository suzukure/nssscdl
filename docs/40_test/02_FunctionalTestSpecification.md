# 機能テスト仕様

## 1. 位置づけ

本書は機能要求 `REQ-001`〜`REQ-321` に対する要求ベースのSystem/Acceptance Test Case Specificationである。
期待結果は要求仕様を正とし、未確定のUI部品名・API Path・DB物理名には依存しない。

各テストケースは `01_TestPlan.md` の標準Actor、時刻、Reservation、Provider Stubを使用する。
同一テストケースで複数ACを検証する場合でも、`04_RequirementsTestTraceability.md` からAC単位で追跡できる。

## 4. 実装テストへの紐付け

自動テストでは test name / tag / metadata のいずれかへTC IDを保持する。
例: `TC-F-003-05 booking conflict after concurrent reservation`。

APIやUIの詳細手順が確定した時は、本書の「前提・手順」を具体化してよいが、ACと期待結果を変更する場合は要求変更として扱う。
