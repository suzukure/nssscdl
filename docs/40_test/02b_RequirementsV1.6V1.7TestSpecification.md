# 要求v1.6 / v1.7 追補機能テスト仕様

## 1. 位置づけ

本書は、要求仕様 v1.6 / v1.7 で追加・補強された以下のAcceptance Criteriaに対する要求ベースのSystem / Acceptance Test Case Specificationである。

- `REQ-003 / AC-003-021` — 新規予約による既存未開始Reservationの標準／追加区分影響を最終確定前に表示する
- `REQ-301 / AC-301-009` — 複数Schedule変更が競合で全体未適用となる場合の競合説明性

あわせて、基本設計で明確化されたPreview→Confirm間の再検証を、既存 `AC-003-016 / AC-003-018` の回帰観点として補強する。

本書は `02_FunctionalTestSpecification.md` および `02a_ReservationOwnershipTestSpecification.md` を補完し、テストケースIDは既存の `TC-F-<REQ>-*` 系列を継続する。

## 3. 合否判定上の注意

### 3.1 AC-003-021

- 「影響する予約日時」と「変更前後の区分」が最終確定前に確認できることを必須とする。
- 新規予約自身がstandard/additionalのどちらになるかだけを表示し、既存Reservationの直接影響を示さない実装は不合格とする。
- 影響がない場合の具体的な空集合Schemaや文言は詳細設計に委ね、要求以上の固定を行わない。

### 3.2 AC-301-009

- 1回のConflictで、発生済み・発生し得る全競合の完全列挙を合格条件にしない。
- 実装が安全に検出できた競合について、対象・業務理由・最新状態確認手段が提供されることを合格条件とする。
- 再操作時に新しい競合が生じた場合は、再度最新状態を検証し、同じ原則で全体未適用となることを確認する。
